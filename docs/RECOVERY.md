# 下载恢复与验收

## 恢复策略

| 中断阶段 | 用户继续后的行为 |
|---|---|
| HTTP 部分文件有有效检查点、强 ETag、已知长度 | 重算前缀 SHA-256，回退未提交尾部，发送 Range / If-Range |
| HTTP ETag 改变、非法 206、416、服务端忽略 Range | 保留旧尝试，最多一次无 Range 重下；不会拼接不同版本 |
| HTTP 检查点丢失/损坏、文件损坏、旧版部分文件 | 保留为 `payload.part.retained-*`，重新下载 |
| HTTP 已完整下载并提交检查点 | 校验后继续图片/媒体验证、转换、发布 |
| yt-dlp/HLS/DASH 未提交完整输出日志 | 保留旧 `.part`、`.ytdl` 和分片，重新解析并在新尝试目录下载 |
| yt-dlp 已提交完整输出日志 | 校验请求身份、长度、摘要和媒体轨道后复用输出 |
| 合并、转换中断 | 保留源文件；重新运行转换/原生下载，不采用未经校验的输出 |
| SAVING 已记录目标 URI 和摘要 | 沿用发布日志恢复：校验成功则补提交，否则移除自己的不完整目标并暂停 |
| 断网/不满足 Wi-Fi 限制 | 存活服务进入等待网络；服务终止后必须从界面手动继续 |
| ENOSPC / SQLiteFullException | 停止自动 IO 重试；尽力记录明确错误，保留数据；释放空间后继续 |

任务重启恢复为 PAUSED，不开机自启下载，不绕过 Android 前台服务预算。
应用被强制停止时不会运行清理代码；依靠上次持久化的 Room 状态和文件检查点恢复。
Room UI 字节计数可能领先文件检查点，恢复时以经过摘要校验的检查点为准。

检查点不含原始 URL，只保存其 SHA-256；Room 仍包含任务原始 URL，设备本地数据库未整盘加密。
网站已完成输出日志绑定 URL、格式 selector、conversion，避免改变输出要求后复用旧输出。
检查点的摘要验证本地字节一致性，不证明源站真实性，也不能防止源站错误复用同一个强 ETag。

## 保留与清理

- 暂停、断网、失败、进程重启均保留下载目录。
- 重新下载不清空之前的尝试；旧尝试会占用空间。
- 成功发布后清除本任务临时目录；用户明确取消也删除该任务临时目录。
- “清理历史”只清理完成/取消记录，保留失败任务以便恢复。
- “清除临时数据”显示破坏性操作确认，需要先暂停任务，并重置任务进度和验证器。不会删除已发布的用户文件。
- 本版本不自动从 retained 文件中猜测/挑选可用前缀，也不从旧版无检查点文件直接追加。


忽略 Range、断网、暂停后新引擎恢复、检查点/文件损坏、未提交尾部、URL 绑定、检查点写入失败、校验期间取消。

现有原生 DASH 设备测试增加旧分片保留、完成输出复用时不再请求服务器，以及缺片必须失败且不能提交完整输出日志的断言。

## 仍需设备验收

1. 在受控 HTTP 源下载大文件，分别暂停、断网、`am force-stop com.mediaharvester.android`；重开后应保持暂停，继续时发送校验后的 Range，最终摘要与源文件一致。
2. 下载受控 HLS/DASH，在分片中间终止应用。重开继续应显示“重新下载”，保留旧尝试，最终媒体包含完整轨道；缺片时不得完成。
3. 在合并/转换、完整输出日志写入后、SAVING 复制中间分别终止进程，验证重试和发布日志；不得误删已完成的用户文件。
4. 在专用测试设备制造空间不足，验证错误、文件保留、释放空间后继续，特别覆盖检查点和 Room 写入本身失败。
5. 测试 Android 15 dataSync/mediaProcessing 预算耗尽、后台启动拒绝、Doze、OEM 电池管理；不得自动循环启动服务。
6. 实体设备断电和文件系统/硬件写缓存故障需要单独验证。文件和目录同步提供可验证的恢复边界，不构成所有硬件上的零数据损失承诺。

本次云环境没有 `/dev/kvm`，未启动 Android 模拟器，也未连接真机；设备测试编译与实际执行必须区分。
原生转换/图片发布已有测试保留，但本次不能声称它们在设备上完成回归。
